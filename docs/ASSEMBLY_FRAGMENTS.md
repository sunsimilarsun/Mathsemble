# 卷内分值与稳定片段

这是本轮开发中的可选能力。旧题卡不需要添加字段或改写正文；没有显式片段锚点的题卡和知识笔记继续整篇加入。这里的分值属于本次方案，不写回题卡，也不代表自动评分。

## 方案兼容

继续读取方案 v1、v2、v3，在内存补齐现行课程、排版默认值，读取不写文件。没有分值和片段引用时，正常保存仍使用 v3。只要任意条目设置分值或片段引用，就保存为 v4。

从已打开的 v1–v3 文件增加这些特性后，必须“另存方案”；原文件保留。覆盖保存会明确拒绝，不能悄悄升级原文件。旧插件不能读取 v4；需与旧插件交换时，清除全部分值、切回整题后另存 v3，不能仅手改版本号。已另存的 v4 文件可正常继续保存，并仍检查外部文件冲突。

v4 顶层字段沿用 v3，条目仅增加两个可选字段：

```json
{
  "entryId": "existing-entry-id",
  "kind": "question",
  "sourceId": "Q-EXAMPLE",
  "sourcePath": "题库/综合题.md",
  "sourceFingerprint": "captured-source-fingerprint",
  "title": "本次显示标题",
  "role": "例题",
  "score": 7.5,
  "fragmentRef": {
    "kind": "question-part",
    "ids": ["domain", "maximum"],
    "scores": {"domain": 2.5, "maximum": 5}
  }
}
```

`score` 只用于题目条目，允许 0 到 1,000,000 之间、最多两位小数的数值；留空表示未设置，不能把空白当作 0。整题和已选小问集合都可指定总分。知识小节和编排分区不能评分。

`fragmentRef.scores` 如存在，必须为每个所选小问提供分值，不能包含未选 ID。总分由这些分值精确到分位求和；显式 `score` 与合计不相等会被拒绝。未全部填写时不形成总分。修改所选 ID 集合或切回整题，会清除旧内容的总分；若同次明确填写新总分或完整小问分值，则采用新值。仅改标题、角色或重排编排不改变分值。

同一来源仍只占一条编排项，多小问使用一个 `ids` 数组；不会把一个来源重复计为多道题。选择的输出顺序由 `ids` 明确保存。小问标题中的原编号不会自动重编，教师应核对显示内容。

## 题卡的可选锚点契约

使用独立顶格 HTML 注释作为边界，建议标记前后留空行。一个题卡必须恰好包含一个 `stem` 共用区域及 1–128 个 `part` 区域。区域不能嵌套；每个开始标记对应一个结束标记。

```markdown
# 二次函数综合题

<!-- mathsemble:stem -->

已知函数 $f(x)=x^2-2x$。以下各问共用此条件。

![共用图](assets/graph.png)

<!-- mathsemble:end -->

<!-- mathsemble:part domain -->

## 定义域

写出函数的定义域。

> [!answer]- 答案
> 定义域为 $\mathbb{R}$。

<!-- mathsemble:end -->

<!-- mathsemble:part maximum -->

## 最值

求函数的最小值。

> [!answer]- 答案
> $f(x)=(x-1)^2-1\ge -1$，当且仅当 $x=1$ 时等号成立。

> [!solution]- 补充说明
> 可结合抛物线的顶点核对结果。

<!-- mathsemble:end -->
```

ID 使用英文字母开头的 1–64 位字母、数字、下划线或连字符，区分大小写。同一来源内不可重复，不用 `constructor`、`prototype` 等保留字。ID 由作者明确填写；标题、行号、第几问和 `subquestions` 字符串数组都不会被猜成 ID。本阶段只支持上述注释契约，不把普通 Obsidian `^block-id` 自动解释成包含答案和解析的小问。

每个 `part` 内放齐该小问的输入、答案槽、answer、solution 与专属图片；共用条件和共用图放在 `stem`。除可选的文档 H1 标题和空行，所有正文都必须归入这些区域，否则片段选择被拒绝，避免静默丢失题干或答案。选填判断保留现行题干答案槽约定；计算、证明等的 answer 仍须包含完整得分步骤，不因支持片段而改变答案规范。

图片和链接继续按原笔记路径解析。引用式图片、链接、脚注的定义必须随选中内容保留，且所用标签在整篇来源中只有一个定义：题卡可将共用定义放入 `stem`；若定义只在未选小问中，或同一标签在不同位置重复定义，编译明确拒绝，避免选择片段改变引用目标。不会为补依赖偷偷带入另一问的答案。未选小问的正文、专属答案与图像不进入生成讲义；教师归档仍可能保留完整原文和声明资源，其隐私边界不变。

## 知识小节

知识笔记使用 `section` 区域，不使用 `stem`：

```markdown
# 二次函数

<!-- mathsemble:section definition -->

## 定义

完整定义及本节所需图片、引用式链接定义。

<!-- mathsemble:end -->

<!-- mathsemble:section vertex -->

## 顶点

完整性质、说明和例子。

<!-- mathsemble:end -->
```

对应方案引用为 `{"kind":"knowledge-section","ids":["definition"]}`。每个小节须自行包含所需上下文和依赖；不会自动带入“前一个标题”或推断先修内容。

## 变化与失效

移动区域、调整标题不会改变稳定 ID；源文变化仍需按既有流程刷新、核对和接受来源更新。若删除或改名所引用的锚点，方案显示明确缺失并阻断编译，绝不退回“第几个小问”、同名标题或整个题卡。重复锚点、错类型、未结束、嵌套及未归属正文也阻断片段选择。

围栏代码、引用、数学块、一般注释和原生 HTML 内的相似文字不是锚点。对不满足结构契约的卡，整题功能继续保留；需要片段时须由作者显式整理。选择与修改分值通过真实来源扫描、身份检查、来源监听和最终重读验证后一次性应用；失败时不发布部分方案，也不写原文。

带片段引用的编排不能直接同族换成另一来源；即使新题碰巧使用相同小问 ID，也不代表同一内容。须先明确切回整题，再做同族替换。整题分值可以随原有编排身份保留。

## 集成 API

- `core.listFragments(item)` 返回 `{supported, valid, kind, fragments:[{id,title,kind}], issues}`，不自动写锚点。
- `core.resolveFragment(item, fragmentRef)` 返回选定 Markdown、选中片段、共用题干与分值合计；无锚点或不完整依赖抛出明确错误。
- `core.updateEntry(plan, entryId, {score?,fragmentRef?})` 为不可变纯修改；`null` 删除对应可选字段。`core.validatePlan` 严格验证并返回 v3/v4 的规范对象。
- `service.updateEntryContent(plan, entryId, patch, options)` 在真实来源检查后返回 `{plan,index,run?}`；允许的 patch 仅为 `score`、`fragmentRef`。`options` 支持既有 `signal`、`isCurrent`、配置与超时，以及显式选择的 `run`。调用方只在成功返回后替换当前方案，并将返回的派生 `run` 保留为待保存记录。
- 若存在精确匹配的配额记录，修改分值会保留原蓝图、逐槽归属与真实锁，派生新的记录 ID 和方案摘要，不覆盖旧记录。多份匹配记录必须明确选择，不能悄悄退回无配额模式。已归属整题配额的条目不能直接改成小问片段；未归属的其他条目仍可选片段，但既有配额、来源去重和题族上限继续核对。方案和派生记录仍分别保存。
- 覆盖旧方案时错误码 `PLAN_V4_SAVE_AS_REQUIRED` 表示必须另存，不能据此自动覆盖旧文件。
- 学生版和教师版的题号后直接接题干，小问使用原有编号和正文。本次分值保存在方案中。编译结果的 `sourceMap` 可携带 `fragmentRef`、`score`，原始来源快照保留全文。
- `assembly-fragments.cjs` 为纯函数模块；内嵌包先提供 `MWB_ASSEMBLY_FRAGMENTS`，Node 测试使用正常 CommonJS 加载。没有新增题卡 YAML 必填字段。

本文说明数据和源码契约；自动化测试、真实 Obsidian 和实际 PDF 的完成状态分别记录，不由本文宣称全部验收。
