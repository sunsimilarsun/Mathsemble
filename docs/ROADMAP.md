# Mathsemble 路线图

当前版本为 [0.2.4](https://github.com/sunsimilarsun/Mathsemble/releases/tag/0.2.4)。书写契约以 [Markdown 规范](MARKDOWN_SPEC.md) 为准；历史演进见 [变更索引](CHANGELOG.md)，当前流程与保存范围见[产品设计](PRODUCT_DESIGN.md)，实现与验证状态见 [功能矩阵](FEATURE_MATRIX.md)。0.2.3 的本地及 Linux／Windows 检查、真实 PDF 与用户验收边界见[发布记录](TESTING_RELEASE_0.2.3.md)及[外观记录](TESTING_APPEARANCE_20261109.md)，不沿用旧 0.2.1 的待验收状态。

## 当前：选材、编排与排版输出

- 在既有诊断中定位预览问题及原文；可靠匹配时精确到行，否则标明题目／文件范围，原文变化后拒绝旧定位。
- 从当前筛选的全部题目中按数量生成候选，人工预览、移除或重抽后显式加入编排；排除已用题及身份冲突，不修改源题卡。
- 独立预览编排支持连续看题、排序、本次标题和角色修改；题干编辑回到原文。入口、刷新与保存提示按选材、编排、排版输出统一。
- 分区可连同下方题目和知识整体拖动、上下移动或按分区序号定位；保留首分区前言，普通内容仍单项移动，移除分区标题保留正文。
- 方案已保存课程信息与默认排版，生成讲义传递试听属性；A4 可显式应用设置回编排草稿，旧方案兼容读取。
- 临时 A4 预览与保存讲义副本分开：反复预览不新增 Markdown；来源目录内 Markdown 变化后返回编排核对并重新预览，诊断指向原题卡或知识笔记。单独打开讲义副本仍使用普通文件流程。
- 保留默认／双列／试听外观、单份讲义双版导出、手动混编与方案保存。0.2.4 的新功能需单独记录验证，不把 0.2.3 的验收等同于新功能验收。

## 优先：完成真实教学输出验收

1. 在 Windows/macOS 的真实 Obsidian 中，以默认明暗主题及一种第三方主题验证阅读、实时预览、A4 与 PDF。
2. 用一份复杂长讲义和一套混合题型试卷复核学生／教师两版：没有教师答案残留，题目完整，公式和题图不裁切，留白总高不减少。
3. 记录目标提交、宿主版本、主题、页数、截图、留白报告和失败清单。测试夹具通过不能替代此项。
4. 继续覆盖原生公式内部答案槽、脚注、嵌入、TikZ 和复杂 Markdown 上下文；未支持的结构应明确诊断。

## 随后：提高维护性与导出可靠性

1. 逐步拆分源码中的解析、版本投影、分页、资源导出和宿主适配模块，保留可从源码干净构建的安装产物。
2. 给资源内联增加总截止时间、取消机制及单次导出缓存；覆盖关闭预览和网络不结束的情况。
3. 扩展错误定位的来源覆盖，保持源文变化检查和诊断／打印内容隔离。
4. 持续将新模板和失败样例纳入回归，维护单一元信息字段约定；不凭文件名或路径补造身份、知识点或来源。

## 后续产品能力

后续按需求增加多篇讲义导出队列、题型配额、题族驱动组卷、知识小节截取及黑白／彩色主题。

以上尚未实现，需要独立需求与验收。

## 发布条件

- 目标提交通过干净构建、全量测试、模板检查和发布预检，浏览器用例无跳过。
- 完成 [宿主验收清单](OBSIDIAN_HOST_ACCEPTANCE.md)，确认真实长 PDF 和学生输出。
- 版本、标签、对应发布说明和三个安装文件保持一致；不覆盖旧 Release。
- 按 [发布指引](PUBLISHING.md)执行，社区审核状态以实际结果为准。
