# TikZ 字母在 PDF 中丢失的修复

适用源码：0.1.15，2026-10-28。本次同步源码和安装产物，不创建新 Release。

## 原因

教师预览在 Obsidian 文档中运行，能够使用 TikZJax 注入的 TeX 字体。PDF 则来自隔离的 HTML；原来的 `extractMathCss()` 仅复制 MathJax 样式，遗漏了 `cmmi10`、`cmr10` 等 TikZ 字体。

本机 TikZJax Next 0.2.3 把字母编码为 Unicode 私用区字符，并通过 SVG `text` 的 `font-family` 指定字形。隔离页面缺少对应字体时，普通字体无法补上这些字形，因此图形线条保留而字母消失。实际失败样本的 PDF 仍含私用区字符，但缺少标签对应的 TeX 字体；截图也确认 TikZ 字母缺失。

## 修改

- 从待导出 SVG 的 `text`、`tspan`、`textPath` 收集实际字体依赖，复制匹配的 `@font-face`，包括媒体／条件规则中的声明。
- 沿用资源内联流程，将外部字体地址转换为 data URI；已内嵌的字体数据直接保留。
- 在导出克隆中固定计算后的字体族、字号、字形、字重和伸缩属性，保留由宿主 CSS 提供的文本字体样式。预览原 DOM 不变。
- 保留普通 MathJax 样式和导出内容安全策略；不改变 TikZ 源码，不放宽 `foreignObject` 等过滤规则。

## 验证与范围

`tests/tikz-export.test.cjs` 使用自制私用区字形字体，离线检查字体筛选、相对 URL 内联及缓存、嵌套字体规则、带引号的后备字体列表、普通 MathJax 规则、原 DOM 保持，以及隔离页面的字形几何和渲染墨迹。修复前该场景可复现字体缺失。

另外使用 TikZJax 的真实 `cmmi9` 小字号字体，经生产 `exportHtml()` 和独立 Chromium 页面生成修复前后 PDF。渲染图确认修复后 O、A、A′、P 均清晰可见，`pdffonts` 确认 `cmmi9` 已嵌入并子集化。第三方字体与验证产物仅存临时目录，不随源码提交。

本机带 Chrome 的检查另发现现有外部模板验收中的四项不一致：单选模板缺少 `object_type`，两份模板的知识点字段与断言格式不同，模板目录新增 `题库` 子目录。它们属于模板测试／内容库状态，不在本次字体修复中修改；不能把这次全量检查表述为全部通过。

隔离 Chromium 回归和 PDF 检查不能代替完整的 Obsidian 多主题、多系统验收。安装产物与源码通过构建一致性检查，宿主重新加载插件后生效。
