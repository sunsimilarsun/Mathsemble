# Mathsemble privacy and security notes

These notes cover data handled by Mathsemble 0.6.0. Earlier verification of the P2 features is recorded in [P2 implementation](P2_IMPLEMENTATION.md).

- The application is local-first and does not implement analytics, telemetry, accounts, or application-managed cloud sync.
- The selection index keeps a rebuildable copy of indexed Markdown and metadata, including teacher answers, in the local Obsidian profile's IndexedDB. Each vault path has its own index. To remove the copy for the current vault, run the command “清除本机选材索引”. The next browse refresh can rebuild it from the source files.
- The plugin reads Markdown from the current note, folder-based exam collection, or configured question/knowledge directories. Assembly schemes store references, ordering and course/output settings; explicitly saved handout copies contain compiled Markdown. Temporary A4 previews use in-memory snapshots without creating a handout file. It updates frontmatter after a direct user action to set a teaching role, or changes the current question heading after the user explicitly invokes the H5 conversion command. Preview, export and the Reading View answer toggle do not rewrite source notes.
- The plugin may request external HTTP(S) resources when a rendered document references remote images/fonts. Remote hosts then see the ordinary request. The feature should not be described as fully offline when printing content that references external resources.
- The plugin can read explicitly referenced `file://` images/font resources located outside an Obsidian vault. The print routine writes temporary HTML to the operating-system temporary directory, then deletes that directory in its `finally` cleanup. Electron handles PDF generation locally.
- Exported PDFs/HTML are saved into the vault's `ExamExports/` folder and are not automatically shared externally by this plugin.
- Each export also writes a persistent local record under `Mathsemble/导出记录/`, including source identifiers/digests, output status, settings, runtime information and a resource manifest. This lightweight record does not contain full source text or resource bytes, but may include local paths and titles and should stay with the teacher.
- Material archiving is optional and explicitly selected in the export window. It writes captured original Markdown (including answers), hidden teacher media, applicable scheme/source-map snapshots and captured output artifacts under `Mathsemble/材料归档/`. These are teacher materials, even when only a student PDF is exported. They are not injected into student output and are not automatically transmitted. The user should distribute the reviewed student PDF/HTML, not the archive or record. Normal Obsidian or third-party vault sync, if configured by the user, may sync these files independently of Mathsemble.
- Saved quota blueprints and run records live under `Mathsemble/组卷蓝图/` and `Mathsemble/组卷记录/`. Run records store source references/digests, assignments and locks; they do not record whether a student actually used or was taught a question.
- **Unreleased P2 — actual-use ledger:** explicit teacher actions append local events under `Mathsemble/使用账本/`, separated by the chosen class/course codes. No student roster is required. Events retain the activity/date, source ID or path identity, full historical Markdown (including answers), content hashes, scheme snapshot digest, entry identity and any selected fragment/score. A correction revokes an event for statistics but does not delete its original text. Repeated submission of one action does not create another use. Exporting, saving or presenting a question never automatically records teaching, assignment or student mastery.
- **Unreleased P2 — import staging and transfer:** `Mathsemble/待入库/` retains original uploaded bytes, proposed files, mappings, loss reports and creation/reversal logs. Import requires explicit confirmation and creates new targets; it does not silently merge IDs or overwrite existing content. Undo only removes files with a matching batch creation receipt and unchanged contents; later user edits, replacements and uncertain ownership are preserved. Re-imported plans, opaque sidecars and archives use separate `Mathsemble/组题方案/`, `Mathsemble/导入旁车/` and `Mathsemble/导入归档/` locations. Carrying a historical sidecar does not reactivate its internal references.
- P2 transfer packages may contain full teacher source, answers, media, plans and any explicitly included sidecars or archives. They are teacher materials, not reviewed student handouts. Missing dependencies, unsupported embeddings and uncaptured SVG references remain reported limitations; a partial package is not a complete reproduction. This package format is not QTI. User-selected downloads, sharing and external applications remain under the user's control.
- P2 fragment selection and scores belong to the scheme, not source frontmatter. Legacy notes remain usable in full; selecting a part does not remove the rest of the source from a teacher history snapshot. Schemes with these optional fields use v4 and must be saved separately from an opened v1–v3 file. Released 0.3.0 cannot read v4. See [fragment and version compatibility](ASSEMBLY_FRAGMENTS.md).
- Usage history, original import bytes, mappings, correction/creation logs, run sidecars and archives are durable records, not rebuildable caches. Back them up with the source vault and compatible schemes. “Teacher materials” describes their intended audience; these ordinary vault files are not automatically encrypted or protected by a separate access-control system. User-configured vault sync or backups may copy them independently of Mathsemble.
- Resource preparation uses per-resource timeouts, a total deadline and cancellation. A preview freezes observed resources in a shared in-memory session (default 64 MiB of unique bytes), including the same session across paired exports. Local vault resources are rechecked by SHA-256; remote resources are stable after capture within that session. Unsupported embeds and SVG external references are reported as capture limitations, not promised reproducible. Cancellation does not retract files already saved or undo a file write already submitted to the host. Closing a preview clears its resource session when active export ownership has ended; persistent records and archives remain until the user removes them.
- The isolated Electron window uses `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`. Print content strips script, iframe and inline event attributes and restricts its CSP. Those safeguards mitigate risk but have not undergone an independent security audit.
- Acknowledged rendering failures can produce incomplete PDF content. Visible warnings and source-file review remain essential.
