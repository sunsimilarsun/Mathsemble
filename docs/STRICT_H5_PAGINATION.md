# 0.1.15：五级题目边界与严格分页

日期：2026-10-26。代码基线：`6663af8345a7ae697d1616da4a84381d690408b3`（0.1.14）。本轮不创建正式 Release。

## 规则

- 讲义以顶格 `##### 例1／变式1／练习1／检测1／题1／第1题` 开始题目；到下一个 H1—H5 或文件结束。H6、小问、横线和交替答案不结束题组。
- 先扫描源 Markdown，再加入不改变源码行数的临时标记；按同一完整文档渲染后核验标题数量、级别、顶层结构及顺序，最后生成内部题目容器。标记删除，不写入原文。
- 新讲义生产路径使用 `strict-h5`，不再调用旧 DOM 题标猜测。历史无策略直接调用保留兼容测试，但不会冒充新规则下已识别题目。
- 每题以当前输出版本实测：不超过版心则整题同页；超过版心则新页起排，然后按现有步骤／列表／留白块续页。第一页总标题不单独制造标题页。
- 单题卡和文件夹组卷沿用文件级题目容器，并使用相同严格策略。
- 题目范围显示只在预览克隆上绘制无布局尺寸的轮廓；范围、提示和逐题页码可复制。转换题标命令仅在显式执行时修改当前行。

## 验证与边界

覆盖 H5/H6、代码／引用／数学／注释排除、Setext、空题、旧题标提示、多个 answer 的小问交替、编号重复、全篇引用链接、源码 Callout ID 保持、边界缺失／乱序拒绝、短题当前页／新页、长题新页及首步续接、solution 计入总高、学生全量留白、组卷题号、MathJax SVG 原节点移动、预览与打印一致性、PDF HTML 策略保留及实际 Modal 方法调用。

CommonMark 夹具由 markdown-it-py 解析并用受控 Callout 适配器生成，测试校验投影源码与夹具匹配；不新增运行时依赖。Chromium 使用真实排版，Obsidian API／MarkdownRenderer 仍为受控替身，不能代替完整桌面宿主和用户讲义验收。

本轮不重写数学内容，不压缩学生书写空间，不保证任意原生 HTML／第三方扩展或省略引用层级的复杂结构。不能匹配源码边界时失败退出。旧式无题标散文不能保证自动发现漏题。

详见 [Markdown 书写规范](MARKDOWN_SPEC.md) 与 [五级题目标注模板](../templates/讲义_五级题目标题.md)。

本地验证：`CHROME_PATH=/usr/bin/chromium npm run prepublish-check` 全部 162 项通过，0 失败、0 跳过，其中真实 Chromium 子场景共 68 个。另生成 5 组样例 PDF（短题、长题、交替小问、学生长留白、MathJax SVG），实际页数均与分页报告相同，并检查长答案续页渲染图。以上为受控样例，不等于用户实际 Obsidian 宿主验收。
