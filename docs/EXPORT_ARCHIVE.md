# 媒体冻结与导出归档

本文对应 2026-11-17 本次开发实现。Mathsemble 会为 A4 导出保存独立记录；需要保留原题、媒体和输出时，可同时生成教师材料归档。正文仍以原 Markdown 为事实源，组题方案保持 v3。

## 使用方法

1. 保存原 Markdown，打开题卡、讲义、文件夹组卷或编排的 A4 预览，检查当前版本与排版。
2. 在“更多”中按需勾选 **同时归档本次教师材料（原题、图片、方案与输出）**。默认不勾选；每个新预览窗口单独选择。
3. 按原有方式保存当前版 PDF、双版 PDF 或 HTML。导出文件仍保存在 `ExamExports/`，归档不改变其保存路径与版别规则。
4. 完成后查看“导出记录／教师材料归档”结果和提示。可点击打开对应记录或归档清单；记录失败时，原输出的保存结果仍单独显示。

每次操作分配新的记录 ID，不覆盖历史记录和归档。归档选项在操作开始时固定；取消不会删除已保存的文件，也不能撤回已经开始的 Vault 写入或提交给系统的打印任务。

| 默认目录 | 内容 |
| --- | --- |
| `ExamExports/` | 本次正常导出的 PDF、HTML |
| `Mathsemble/导出记录/<记录ID>.json` | 轻量记录：来源摘要、设置与运行环境、产物状态和摘要、资源清单、归档结果 |
| `Mathsemble/材料归档/<记录ID>/` | 勾选归档后保存的原文、编排材料、媒体、产物和最终清单 |

轻量记录不保存源文／编排全文或媒体字节；需要这些材料时应在导出前勾选归档。记录及归档目录是持久资料，不属于可随意清理的运行缓存。

## 教师材料与学生输出

**材料归档包含原题答案、解析及教师专用图片，应按教师私有资料保管。** 即使只导出学生版，归档也保存当次捕获的完整原文，并尝试收集原文中可识别的隐藏媒体依赖。分发学生材料时选择核对后的学生 PDF／HTML，不分发整个归档目录或轻量记录。

原文、方案和资源清单保存在独立目录，不会因勾选归档而塞进学生 PDF／HTML。学生输出继续按现行答案槽与 Callout 规则投影；归档不会扩大学生可见内容。记录可能含原路径、题目标题及运行配置，也适合留在教师侧。

## 冻结、变化检查与重新读取

预览在图片进入测量前捕获资源字节，后续排版和导出使用这些固定字节。同一个预览会话以及同次双版导出共享资源；热缓存淘汰不会触发重新获取已冻结资源。

导出前对已经识别为当前 Vault 内的本地图片、字体重新读取并计算 SHA-256，与捕获值比较。因此，即使路径、文件大小和修改时间未变化，替换图片内容仍可使旧预览失效。媒体修改、删除或改名事件也会提示来源变化。已变化的资源不会在旧预览中被静默换成新图。

- 普通题卡或文档：保存更改后点击“重新读取源文”。
- 独立打开的讲义副本：点击“重新读取讲义”，只更新该副本。
- 从编排打开的临时 A4：点击“返回编排更新”，刷新素材、核对并按需接受来源更新，再打开新的 A4 预览。

“重新排版”只重排当前已捕获的内容，不表示接受新原文或新媒体。重新读取成功后会建立新的媒体会话。关闭预览、插件卸载及双版工作窗口退出会按资源归属清理监听器与会话，工作窗口不会销毁主预览借给它的会话。

每个媒体会话默认最多冻结 **64 MiB 不重复资源字节**，相同摘要的内容去重。它不是单个 PDF 的体积上限，也不包含全部运行内存开销；Base64、DOM 和输出副本还会占用内存。超出预算会停止当前操作，不会以重新下载或丢失冻结关系的方式继续。可缩减图片体积、拆分材料后重新打开预览。

## 如何理解结果

输出文件、轻量记录、材料归档分别报告结果。记录或归档失败不等于 PDF／HTML 保存失败。

| 产物状态 | 含义 |
| --- | --- |
| `prepared` | 已生成字节，尚未确认保存；仅打印也可以保持此状态 |
| `saving` | 写入已经开始，尚未返回；界面处理中使用 |
| `saved` | Vault 保存调用已成功，记录实际路径 |
| `unverified` | 写入返回错误或结果不确定；文件可能已经落盘，应核对目标文件 |
| `failed` / `cancelled` / `not-run` | 对应失败、取消或尚未执行，不推断保存成功 |

双版导出会先准备两版，再开始保存。第二份失败时保留第一份的 `saved`；若第二份写入结果不确定，记录为 `unverified`。取消发生在成功写入之后，也会保留已保存事实。打印报告单独保留，系统接受打印任务不代表纸张已打印成功。

材料归档的 `complete` 表示**本次捕获输入与已观察资源范围内**的材料已保存，最后的 `manifest.json` 已写入；它不等于本次所有输出都成功。`partial` 表示清单已保存但存在明确缺口，例如资源遗漏、摘要不符、产物字节未捕获、SVG 外部引用或库外文件未复核。应查看清单中的 warnings／omissions，而不是据此推断缺失资源可复现。

归档写入中途失败不会生成“完成”清单；目录可能留有部分文件。写入返回错误时可以是 `unverified`，不能仅凭异常断言磁盘上没有文件。模块不会删除半包、覆盖旧包或回滚已经成功的输出。当前记录在收尾时写入，不提供宿主崩溃后的事务恢复。

## 归档中的材料与映射

`manifest.json` 保存本次输入、运行配置、资源及产物状态，并列出实际写入文件的字节数和 SHA-256。典型内容包括：

- `sources/0001.md` 等：捕获的原 Markdown，保留 BOM、CRLF 等原字符串内容；`inputs.sources[].archivePath` 对应原路径，`textUtf8Sha256` 明确表示该字符串的 UTF-8 摘要。
- `compiled.md`、`source-map.json`：从编排生成的完整正文及来源映射，适用时保存。
- `plan.v3.json`：经现行校验器确认的 v3 方案快照；不向旧方案增加归档字段。
- `media/<摘要>.bin`：去重后的媒体字节；通过资源清单的 `mime`、`localPath`／脱敏 URL、`representation` 和 `archivePath` 辨认来源与表示形式。
- `artifacts/0001.pdf`、`.html` 等：捕获的生成产物；清单中的 `state` 仍区分已保存、未保存和结果不确定。

归档原文保留原有引用，媒体使用独立摘要文件名，**目前不是打开即用的可迁移导入包**。恢复或迁移时需要按 manifest 映射原路径与媒体；当前没有自动重写全部原文链接、自动安装第三方渲染器或一键导入为题库的功能。不要把 `.bin` 文件名单独当成原笔记资源路径。

## 捕获范围与验证边界

资源清单覆盖已观察并成功捕获的图片、字体以及可识别的原文媒体声明。远程资源只保证同会话捕获后的字节一致，不保证多个 URL 来自服务器的同一瞬间。库外文件、SVG 内部外链、动态第三方内容、视频／音频等未支持嵌入不能被默认为已完整收集。清单保留这些限制；归档不是整个 Vault、全部插件或未来运行环境的备份，也不保证将来重新渲染得到位级相同的 PDF。

2026-11-17 已在 Windows Obsidian 1.15.1 的真实安装插件中验证：同大小、近似保持原修改时间的图片内容变化被摘要复核阻止；重新读取恢复；双版原生 PDF、学生 HTML、可见／教师隐藏图片归档；临时编排的 v3 快照与来源保持。该批运行 bundle SHA-256 为 `7a5de801d61e61497d866cf5bdb51de62afc6e64e0d21242a01c45f45b674dab`，本地原始结果位于 `.local/p0-p1-20261117/native-evidence/p1-media/result.json`。

原生结果中的字节、摘要与状态检查，不替代所有版式、远程服务、全部第三方插件或跨平台的验收；PDF 视觉检查须与对应图像证据一并判断。自动化另覆盖资源预算、取消、写入后报错、部分保存、归档冲突、记录失败及监听生命周期。此处证据只适用于该批实现，不改写 [0.2.5 历史测试记录](TESTING_0.2.5.md) 的验证范围。
