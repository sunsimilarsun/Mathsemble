# 按配额组卷

本文描述包含“按配额组卷”入口的当前开发实现；不将本次增量写成已发布 0.2.5 的既有功能。普通手动编排和“条件抽题”仍可独立使用。

## 从条件到完整候选

1. 打开“选材与编排”，设置题库目录，点击“应用目录并刷新”。在选材页的条件抽题工具栏点击“按配额组卷”。
2. 填写蓝图名称。为每行填写名称、题数和筛选条件；可增加行、上移或移除行。“更多条件”中有学科、知识点、方法、教学角色和来源。
3. 点击“保存蓝图”，以后可从“已保存蓝图”重新打开。保存蓝图只保存配额条件，不加入题目，也不保存当前方案。
4. 点击“生成候选”。查看每行的需要数、候选池、锁定数、分配数及题目正文。
5. 按需锁定题目、重抽未锁定题或“换一道”。全部行满足后，点击“应用完整配额”；插件重新扫描并核对来源，通过后一次加入编排。
6. 返回工作区后点击“保存方案”或“另存方案”。方案保存成功后，再保存本次配额归属和锁定记录。

未选条件表示不限。同一条件多选表示“或”，不同条件之间表示“且”，沿用普通筛选的语义。例如难度选 2、3，题型选填空，表示“难度为 2 或 3 的填空题”。知识点筛选沿用已有的标签及知识笔记关联规则，不会自动改成“每个知识点都必须具备”。

配额最多 64 行，每行 1–1000 题，各行合计最多 1000 题。应用后的方案仍受原有 1000 项上限约束，知识和分区也占方案容量。

“每个题族最多题数”留空表示不限，填写正整数后约束整个方案，包括未计入配额行的原有题。题族按已有 `family_id` 精确分组；未归族题各自独立，不共同消耗一个空题族名额。非法题族字段会提示处理，不自动归到其他族。

## 一题只计入一行

分配同时考虑所有行，不按行先后逐行抢题。例如第一行可选甲、乙，第二行只能选甲，各需一题，完整分配应为第一行选乙、第二行选甲。

一题即使符合多行，也只能占一个槽位。已有题的 ID 和路径继续占用去重范围，身份冲突的题不能入选。候选池覆盖完整扫描结果，不以界面一次显示的 50 道为抽题边界。

配额数量指该行的最终总数。要把方案中已有的题计入某行，在该行的“将编排中的题目计入此行”选择题目，再点击“固定到此行”。应用时保留该题原来的位置、编排项 ID、本次标题和角色，不再次追加。

方案中其他已有题仍保留并占去重与容量，但不会自动抵扣某行配额。一个已有题不能同时计入多行。删除行、减少数量或修改条件后，原锁定可能不再有效，需要先解除或重新明确归属。

## 锁定、重抽与换题

- **锁定**保留题目及所属槽位。锁定不是筛选或来源检查的豁免；来源变化、身份冲突或不再符合该行条件时仍会拒绝应用。
- **重抽未锁定题**保留明确锁定项，为其余槽位重新生成完整分配。它不保证每次都出现不同组合。
- **换一道**只更换当前槽位，继续满足原行条件，保留其他槽位。已锁定的题须先解锁；没有合法替代时保留原候选。
- **同族换一道**进一步要求候选具有相同的有效 `family_id`；仍核对行条件、重复题和整个方案的题族上限。题族未知时不能推断同族替代。
- **取消计入**解除已有题的行归属。原题仍在方案中；如果当前候选因此失效，需重新生成，不能将它静默改成新增题。

普通候选的锁定或解锁，在原候选仍有效时保留当前题目，不需要为此重新抽题。它不会使已经失效的候选恢复有效。题干预览和上述候选操作都不修改原题卡。

## 缺题、超预算与来源变化

| 提示状态 | 含义与处理 |
| --- | --- |
| 配额全部满足 | 可核对题目并完整应用；应用前仍会重新检查来源 |
| 完整候选池分配不足 | 当前条件和锁定下没有完整分配；调整配额、补题或显式解锁后再生成 |
| 计算超出预算 | 本次计算未完成，不能据此断定题库无解；可缩小问题后重试 |
| 操作取消 | 本次操作未提交完整编排，原方案保留 |
| 来源、目录或方案已变化 | 原候选失效；核对并刷新后重新生成 |

缺题不会自动放宽筛选，也不会把部分行先加入。单行各自看起来有足够题目，仍可能因共享同一批题而整体不足；表格中的候选池数量不等于各行可以独占的题数。

生成候选到应用之间，题库中的编辑、删除、改名、新增重复 ID，或当前方案、目录设置的变化，都可能使候选失效。应用失败不提交部分结果；旧编排、源题卡和已经保存的方案文件保持原样。

## 三种文件，各自独立

| 文件 | 默认目录 | 保存内容 |
| --- | --- | --- |
| 蓝图，`schemaVersion: 1` | `Mathsemble/组卷蓝图/` | 名称、稳定蓝图 ID、修订、配额行、条件与约束；不含本次已选题或锁定 |
| 方案，现行 v3 | `Mathsemble/组题方案/` | 来源引用、顺序、本次标题与角色、分区、课程信息和排版设置 |
| 配额记录，`schemaVersion: 1` | `Mathsemble/组卷记录/` | 当次蓝图快照、前后方案摘要、随机种子、算法版本、逐槽归属、真实锁定和来源扫描摘要 |

蓝图和配额记录不向 v3 增加 `planId`、`blueprint`、锁定或题族字段，也不与方案 JSON 混放。它们不是题卡正文或媒体的备份；需要保存原文与资源时，参见[导出记录与材料归档](EXPORT_ARCHIVE.md)。

方案仍可读取 v1、v2、v3。打开旧方案只在内存中归一，显式保存才写成现行 v3；没有配额记录、记录损坏或记录版本不受支持，都不妨碍旧方案独立打开和使用。

蓝图的最小结构示例：

```json
{
  "schemaVersion": 1,
  "blueprintId": "blueprint-demo",
  "revision": 1,
  "title": "基础题与提高题",
  "rows": [
    {
      "rowId": "basic",
      "label": "基础填空",
      "count": 3,
      "filters": {"questionType": ["fill_blank"], "difficulty": [1, 2]}
    },
    {
      "rowId": "advanced",
      "label": "提高解答",
      "count": 2,
      "filters": {"questionType": ["short_answer"], "difficulty": [4]}
    }
  ],
  "constraints": {"uniqueQuestion": true, "maxPerFamily": null}
}
```

行 ID 在重排行时保持不变；槽位由行 ID 和行内序号定位。记录中的 `origin: "plan"` 表示显式计入的已有题，包含 `existingEntryId`；`origin: "candidate"` 表示本次新增题。应用后的归属另有实际 `entryId`。题目 ID、源路径和源指纹分别记录，不把指纹当作题目身份。

## 保存失败与只读核对

方案和配额记录分两次写入。若界面提示“方案已保存；配额记录尚未保存”，成功的方案不会回滚或删除，不能把它理解为两者都已保存。保留当前工作区，处理失败原因后再次保存方案，可重试尚未完成的记录；待保存记录只在当前工作区内存中，关闭或重启后不会自动恢复。未知的旧记录不会被覆盖。蓝图保存也会检查本视图读取后的外部修改或删除，遇到冲突时应先核对文件或另存。

打开“按配额组卷”，展开“查看当前方案的配额记录”，选择记录并点击“核对记录”。插件会检查它是否匹配当前方案，以及来源和配额是否仍有效；不匹配时明确提示。

**当前记录核对为只读功能。** 它不会把历史记录恢复成任意可编辑候选，不会自动重新抽题、改写方案或恢复过去的题库。打开一个蓝图也不会自动恢复上次的锁定。记录中的随机种子用于追踪当次分配；题库或算法变化后，不能只凭种子承诺恢复旧组合。
